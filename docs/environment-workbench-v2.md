# 摄影环境工作台 V2

## 目标

把首页已有的环境事实扩展为可解释、可验收的摄影环境工作台，同时保持 Today 只有一个主机会对象。工作台用于查看当前环境、连续天气采样、候选摄影窗口、摄影影响和数据限制，不替代安全预警，不制造成功概率。

## 数据边界

工作台使用两类数据：

1. Context V5 当前事实：天气、温度、总云量、降水、风、能见度、空气质量、太阳几何与数据新鲜度。
2. Sky Window 时间线增强：未来 6–72 小时、固定 15 分钟步长的受限采样，以及候选窗口、置信等级和缺失来源。

Sky Window 保留原有 `current`、`windows` 和 `bestWindowId` 字段，同时增加向后兼容的 `samples`。单个采样只包含移动端图表需要的轻量字段：

- UTC 有效时间与条件等级；
- 太阳高度和天文夜状态；
- 总云量、高云、中云和低云；
- 降水概率、降水量和相对湿度；
- 风速、阵风和能见度；
- Open-Meteo 与 7Timer 的一致性结果；
- 可解释限制项。

请求最长为 72 小时，因此单次响应最多包含 289 个采样点。Flutter 客户端严格校验采样数量、时间范围、15 分钟步长、坐标绑定和数值边界。缺失或不规则时间线整条拒绝，不使用插值补齐。

7Timer 只作为辅助一致性来源，不替代主天气事实，也不被包装为成功概率。时间线失败不会影响 Context、Today 主机会、安全预警或 Explore。

## 页面结构

- 环境总览：场景、新鲜度、最佳候选窗口及峰值时间。
- 当前环境事实：按场景动态排序的事实卡，缺失项目不占位。
- 连续环境时间线：
  - 总云量、高云、中云和低云；
  - 降水概率与降水量；
  - 风速与阵风；
  - 能见度；
  - 候选窗口背景区间。
- 数据依据与限制：展示采样数量、更新时间、过期状态、置信等级和缺失来源。

Today 的环境卡不新增常驻区域。点击卡片直接进入工作台并聚焦对应维度：

| Today 卡片 | 工作台聚焦 |
|---|---|
| 云量 | 分层云量 |
| 降水 | 降水概率与降水量 |
| 风 | 风速与阵风 |
| 能见度 | 能见度 |
| 光线、温度、空气 | 总览 |

## 降级规则

1. 时间线不可用时，仍展示 Context 当前事实。
2. 某一指标全部缺失时，对应图表显示明确空状态，不生成零值。
3. 过期 Context 必须标记为“最近有效数据”。
4. 7Timer 缺失只降低增强置信信息，不影响 Open-Meteo 主时间线。
5. 候选窗口为空不等同于一定不值得拍摄。
6. 所有摄影文案保持条件表达，禁止输出成功概率。

## 验收实验室

Debug 构建保留 `/environment-lab`，支持以下场景：

- 城市落日
- 山地低云
- 湖岸降雨
- 晴朗夜间
- 过期且缺失

支持以下视口和可访问性组合：

| 维度 | 取值 |
|---|---|
| 页面宽度 | 320、390、768 px |
| 字体缩放 | 100%、115%、130% |

## 发布门槛

1. 320 px 宽度与 130% 字体缩放下无 RenderFlex、文字或图表溢出。
2. 过期数据必须标记为“最近有效数据”。
3. 缺失云量、能见度、风或降水时，不生成虚假曲线。
4. 时间线必须满足完整数量和固定 15 分钟步长；否则整体降级。
5. 图表必须标注单位和采样时间。
6. 摄影文案使用“可能”“需确认”等条件表达，不输出成功概率。
7. Sky Window、Open-Meteo 或 7Timer 失败时，Today 主机会和安全链继续独立运行。
8. Flutter 全量测试、Data Broker、Discovery、Raster、Terrain 服务测试以及 Android Debug APK 构建必须通过。
