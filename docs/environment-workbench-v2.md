# 摄影环境工作台 V2

## 目标

把首页已有的环境事实扩展为可解释、可验收的摄影环境工作台，同时保持 Today 只有一个主机会对象。工作台用于查看当前环境、候选窗口峰值采样、摄影影响和数据限制，不替代安全预警，不制造成功概率。

## 数据边界

工作台使用两类数据：

1. Context V5 当前事实：天气、温度、总云量、降水、风、能见度、空气质量、太阳几何与数据新鲜度。
2. Sky Window 增强：当前评估与候选窗口的峰值评估，包括分层云量、降水概率、阵风和能见度，以及置信等级和缺失来源。

当前 Flutter 合约没有暴露完整 15 分钟时间序列，因此图表只连接“当前采样”和“候选窗口峰值采样”。界面必须明确说明采样点之间没有被解释为连续趋势，禁止插值成伪逐小时预报。

## 页面结构

- 环境总览：场景、新鲜度、最佳候选窗口及其峰值时间。
- 当前环境事实：按场景动态排序的事实卡，缺失项目不占位。
- 未来窗口采样：云量、降水概率、阵风、能见度四类图表。
- 摄影解读：结合场景给出条件语言，不把单一环境值改写为拍摄结果。
- 数据依据与限制：展示更新时间、过期状态、置信等级和缺失来源。

## 验收实验室

Debug 构建提供 `/environment-lab`，支持以下场景：

- 城市落日
- 山地低云
- 湖岸降雨
- 晴朗夜间
- 过期且缺失

支持以下视口和可访问性组合：

| 维度 | 取值 |
|---|---|
| 页面宽度 | 320、390、768 px |
| 字体缩放 | 100%、115%、130% |

## 发布门槛

1. 320 px 宽度与 130% 字体缩放下无 RenderFlex、文字或图表溢出。
2. 过期数据必须标记为“最近有效数据”。
3. 缺失云量、能见度、风或降水时，不生成对应事实卡或趋势图。
4. 候选窗口少于两个有效采样时显示明确空状态。
5. 图表必须标注单位和采样时间，不暗示完整连续预报。
6. 摄影文案使用“可能”“需确认”等条件表达，不输出成功概率。
7. Sky Window、Open-Meteo 或 7Timer 失败时，Today 主机会和安全链继续独立运行。
8. Flutter 全量测试、Data Broker、Discovery、Raster、Terrain 服务测试以及 Android Debug APK 构建必须通过。
