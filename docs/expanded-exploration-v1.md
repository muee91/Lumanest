# 主动扩展探索 V1

## 产品目标

扩展探索服务于用户到达陌生区域后的主动认知需求。它不替代地图搜索，也不在每次打开探索页时自动进行深度抓取。基础区域简报保持轻量；只有用户主动点击，或后续 AI 在回答区域事实且需要验证时，才进入扩展模式。

## 两级请求模式

### 前台轻量更新

`activationType = foreground_opportunistic`

仅请求：

- `identity`
- `orientation`
- `photoThemes`
- `practical`

半径策略：

- 本地步行或静止：5 km
- 驾车：20 km
- remote / extreme：50 km

轻量更新用于维持“这里是什么、朝哪里看、适合拍什么、基本实用信息”，不主动触发完整活动与人文搜集。

### 用户主动扩展

`activationType = user_manual`

请求完整八类内容：

- `identity`
- `orientation`
- `photoThemes`
- `happeningNow`
- `places`
- `localTaste`
- `etiquette`
- `practical`

半径策略：

- 历史街区、古镇、村落：15 km
- 景区：20 km
- 其他本地场景：12 km
- 驾车：35 km
- remote / extreme：50 km

扩展模式继续复用已有审核搜索、来源政策、Discovery Worker 与 Crawl4AI 补充正文链路。Crawl4AI 仍不能自行创建候选，未获来源级授权时不得抓取全文。

## 场景化目标

客户端根据 `ExplorationSceneProfile` 解释扩展探索的目标：

- 古镇/历史街区：历史、建筑、街巷、表演、集市、地方味道；
- 城市：建筑、街头人文、近期活动、公共空间；
- 村落：生活场景、地方物产、文化实践、补给；
- 山地：山体身份、观景方向、步行入口、开放状态；
- 高原/荒漠：地貌、道路、合法停靠、通信与补给；
- 湖泊/海岸/湿地：岸线题材、当地活动、进入方式与环境限制；
- 森林：步道、季节变化、进入方式与开放限制。

这些是请求意图，不是事实模板。没有审核证据时必须返回 pending、partial 或 unavailable，不能生成地方软文填空。

## 前端信息结构

扩展结果按四组展示：

1. **适合拍什么**：建筑、自然特征、摄影题材、季节信号；
2. **正在发生**：活动、演出、集市；
3. **这里的味道与人文**：历史、故事、地方食物、特产、文化实践、礼仪；
4. **出发前确认**：路线停靠、补给、开放状态、规定。

每条信息必须展示验证状态：

- `authoritative` → 官方来源
- `corroborated` → 多源核验
- `singleSource` → 单一来源
- `candidate` → 待核实
- `conflicting` → 来源冲突

客户端同时展示来源数量、高等级来源数量、已核验信息数量和简报完整度。来源详情继续使用现有证据模型，不向用户暴露内部 Token、服务地址或抓取配置。

## 状态与缓存

- 主动扩展期间保留当前可用简报；
- pending、unavailable 或网络失败不能清空已有内容；
- 同一区域的后台轻量结果不能覆盖更完整的主动扩展结果；
- 区域发生变化时允许正常替换；
- 只有包含可用事实的新结果才写入本地缓存；
- 自动重试保留原始 activationType，不把主动扩展降级成轻量请求；
- `lastExpandedAt` 只用于当前会话反馈，不作为事实新鲜度依据。

## 成本与安全边界

- 不自动采集小红书或抖音；
- 不把社交热度当作开放、安全或可达事实；
- 不在后台持续高频抓取；
- 不因扩展探索失败阻塞 Today、路线、地图或 AI 通用摄影知识；
- 官方关闭、管制和安全信息仍必须进入独立安全链，普通区域线索无权覆盖安全状态；
- 候选地点不能直接变成摄影导航目标。

## 验收标准

- 自动请求只包含四个核心 section；
- 手动请求包含完整八个 section；
- 所有半径不超过 50 km；
- 主动扩展按钮具有明确进行中状态并防止重复点击；
- 320 px 宽度、130% 字体下无布局异常；
- 四类信息按语义分组；
- 五种验证状态可辨认；
- pending 手动结果保留已有简报；
- 后台轻量结果不能降低同一区域已有简报质量；
- 新区域可以正常替换旧区域。
