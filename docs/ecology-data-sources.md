# 生态数据源与产品边界

栖光的生态信息服务于摄影与区域理解，不建设独立观鸟产品，也不把历史记录或社区投稿包装成实时出现概率。

## 数据源角色

- **GBIF**：默认启用，提供多年公开物种记录的历史基线；输出必须明确“历史记录不代表当前出现”。
- **iNaturalist**：默认启用，提供近九十日研究级公开鸟类观察的聚合信号；只保留观察数量、返回样本分类单元数量和证据时间。
- **eBird**：可选增强，默认关闭。只有后台显式启用且配置 API Token 后才调用；缺少 Token 不降低默认 Provider Hub 健康度。

## 隐私与安全

- 不向客户端或 AI 返回观察者身份、原始备注、媒体地址或单条观察坐标；
- 不尝试还原 iNaturalist 已模糊或隐藏的位置；
- 不把稀有或敏感物种记录转换成导航点、路线节点或打卡目标；
- 生态事实只进入现有自然特征、季节信号和摄影题材链；无可靠事实时整块隐藏；
- 所有措辞使用“历史记录”“近期自然观察”“观察条件参考”，禁止使用“出现概率”或保证现场可见。

## 产品表达

生态事实复用探索页现有的按需“环境与地区线索”入口，不新增常驻观鸟模块。GBIF 显示为“历史生态记录”，iNaturalist 显示为“近期自然观察”，并明确它们只适合作为自然题材、季节和区域理解的参考。摘要卡和详情弹层使用同一事实边界，避免一个入口给出比另一个更强的结论。

## 运行与缓存

GBIF 使用长周期参考缓存；iNaturalist 使用较短缓存并限制为粗略范围、近九十日、研究级鸟类观察。两者失败均独立降级，不影响 Today、路线、地图和安全链。

管理台分别展示每个 Provider 的运行次数、就绪、无数据、不可用、未配置、最近延迟和信号数量。Prometheus 同步暴露这些聚合计数，以及缓存命中、未命中和并发合并次数；指标不包含坐标、物种点位、观察者或原始上游内容。

## 真实场景验收

在部署环境的数据代理目录执行：

```bash
npm run validate:ecology
```

验收工具覆盖杭州西湖、杭州西溪湿地、德令哈、青海湖、伊犁河谷和拉萨河谷等粗粒度场景，只调用 GBIF 与 iNaturalist。输出仅包含场景标签、Provider 状态、信号数量和聚合可达率，不打印经纬度、观察者、原始备注或媒体地址。

`ready` 与 `noData` 均表示上游可达；`unavailable` 与 `unconfigured` 不计入可达。默认要求每个生态 Provider 至少在 50% 的场景中可达，可通过 `ECOLOGY_MIN_REACHABLE_RATIO` 调整；单次超时可通过 `ECOLOGY_VALIDATION_TIMEOUT_MS` 调整。该命令需要在 NAS 或正式部署网络中主动执行，不作为普通 CI 的联网步骤。

## 验收门槛

- 未指定 `include` 时，Provider Hub 默认请求 GBIF 与 iNaturalist，但不请求 eBird；
- eBird 只有在控制台显式启用并配置 Token 后才执行，缺失凭据不构成默认链故障；
- iNaturalist 请求只检索鸟纲、近九十日、研究级、非圈养且具有公开地理信息的记录；
- iNaturalist 响应只输出有上限的聚合数量、样本分类单元数量和证据时间；
- 序列化结果不得包含观察者、原始备注、媒体 URL、单条观察坐标或带坐标查询参数的来源链接；
- GBIF 或 iNaturalist 的无数据、超时和上游错误必须独立降级，不得污染安全链或清除已有区域简报；
- 自动化测试必须覆盖默认源选择、eBird 显式启用、聚合字段上限、隐私字段排除、管理台字段、运行结果计数、Prometheus 指标和真实场景验收器；
- 发布前必须在目标部署网络运行 `npm run validate:ecology`，自动化测试通过不能替代真实上游可达性验证。
