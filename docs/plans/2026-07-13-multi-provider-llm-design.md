# LumaNest 多供应商 LLM 配置中心设计

## 目标与边界

把 NAS Broker 当前单一的 `API Key + Base URL + Model` 配置升级为多供应商档案系统。系统首次进入时保持空状态，不创建、启用或暗示任何默认供应商。只有用户主动新增并保存档案后，LLM 才会启用；没有可用档案时，App 继续使用本地确定性模板。

供应商模板只用于减少录入工作，不代表推荐、授权或自动开通。首批覆盖 OpenAI、Anthropic Claude、Google Gemini、通义千问、DeepSeek、智谱 GLM、Moonshot/Kimi、火山方舟、OpenRouter、Ollama 与自定义 OpenAI 兼容服务。

## 领域模型

每个 `LLMProfile` 包含：唯一 ID、显示名称、供应商 ID、协议类型、API Key、Base URL、模型 ID、启用状态、请求超时、是否允许作为备用、创建和更新时间。API Key 继续由现有 AES-256-GCM 配置存储整体加密，管理 API 只返回是否配置及末四位。

全局 `LLMRoutingPolicy` 包含主档案 ID、是否启用自动备用、按顺序排列的备用档案 ID、单次请求最多供应商尝试数。系统不自动选择主档案，也不把任意环境变量空值迁移成档案。仅当检测到旧配置中存在真实非空 Key 时，未来才可以显示“可导入旧配置”，未经确认不迁移。

## 协议适配器

业务层只调用统一的 `generateStructuredNarrative()`：

- `openai_compatible`：OpenAI、DeepSeek、通义千问、智谱、Kimi、火山方舟、OpenRouter、Ollama、自定义服务。
- `anthropic_messages`：Claude 原生 Messages API。
- `google_generate_content`：Gemini 原生 GenerateContent API。

每个适配器只负责构造请求、认证头和提取文本；统一的结构化 JSON 校验继续在适配器之外执行。模型不得新增地点、坐标、安全结论、链接或动作，也只能改写已成立创作事件。

## 路由、备用与费用保护

默认关闭自动备用。开启后，主模型只在超时、限流、上游 5xx 或网络临时故障时进入备用链。认证失败、余额不足、模型不存在、请求格式错误和结构化输出越权不会盲目重试。

备用顺序由用户显式排列；单次请求最多尝试三个档案，同一档案只尝试一次。所有档案失败后返回本地确定性模板，不把模型故障升级成 App 故障。运行时使用不可变快照，请求开始后不会因管理台切换而中途换供应商。

## 专业管理界面

“密钥与服务”中的单一 AI 表单改为独立“模型服务”工作区：左侧是紧凑档案列表，右侧是结构化详情和状态。顶部明确显示“未配置 / 主模型 / 备用已关闭 / 备用已启用”。

新增档案时先选择供应商模板，再显示协议、官方端点、模型、Key 和高级设置。Base URL 对普通预设默认只读，高级模式才允许覆盖；自定义兼容服务始终可编辑。连接测试必须针对单个档案，显示认证失败、限流、超时、模型不存在、响应异常等稳定分类和最近测试时间，不显示原始上游响应。

切换主模型、启用备用链、删除档案均需明确确认。界面采用严谨的运维控制台风格：高信息密度、克制颜色、明确状态标签、表格化对比、无装饰性动效，并保持键盘操作、可读标签和移动端退化。

## 安全、错误和测试

管理 API 拒绝未知供应商、未知协议、重复 ID、非法 URL、空模型、过长字段、无效备用引用和未启用的主档案。供应商模板由服务端发布，前端不能提交任意协议实现。

测试覆盖：空状态、所有预设、档案增删改、密钥保留和替换、主模型选择、备用顺序、三类协议请求、稳定错误分类、备用触发边界、最大尝试数、结构化输出校验、旧环境空 Key 不迁移、管理 API 脱敏、静态 UI 安全及 NAS 重启持久化。
