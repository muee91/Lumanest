# 环境感知摄影助手：首版产品与技术设计

- 状态：已确认
- 日期：2026-07-11
- 中文名称：栖光
- 英文名称：LumaNest
- 品牌口号：循光而行，择光而栖。
- 首发平台：Android 优先，Flutter 代码结构兼容 iOS
- 首版类型：可运行、具备真实数据闭环的完整 MVP

## 1. 产品定义

这是一个面向自驾、徒步、风光摄影和人文探索用户的环境感知摄影助手。

产品不以“功能入口多”为目标，而是根据时间、地点、天气、地形、路线、周边资源、野生动物信息和用户偏好，动态判断此刻最值得展示的内容。

核心承诺：

> 用户打开 App 后 10 秒内，知道此刻值得拍什么、去哪拍、什么时候拍，以及路上需要注意什么。

产品不替代高德导航、专业气象软件或专业天文规划工具。它负责把分散的数据翻译成摄影师可以立即执行的判断。

## 2. 已确认的设计原则

1. 基础结构稳定，具体内容动态。
2. 没有价值的内容不出现，也不保留空位。
3. 今日页优先给结论，不展示数据仓库。
4. 地图只展示当前意图相关的信息，不默认展示所有 POI。
5. 灵感瓶负责创作情绪，稳定卡片负责行动决策。
6. 安全信息使用固定、高对比、低动效通道，不进入灵感瓶。
7. AI 负责表达、解释和辅助排序，不负责事实认定。
8. 任何核心能力都应具有断网、模型故障或单一数据源失败时的降级路径。
9. 动态背景负责氛围，不承担精确信息表达。
10. 敏感野生动物数据不得暴露精确位置。

## 3. 首版范围

### 3.1 七类情境

首版覆盖以下七类代表性情境：

- 城市：蓝调、天际线、街拍、人流、建筑反光和生活 POI。
- 湖泊：晨雾、倒影、湖岸机位、风力和水面状态。
- 高山：日照金山候选、云层、能见度、风力和山地风险。
- 沙漠戈壁：沙尘、侧逆光、长焦压缩、补给和无人区路线。
- 村落人文：集市、寺庙、街巷、牧群和合规的人文拍摄提示。
- 自驾：沿途机位、光线窗口、加油站、补给空档和停靠节点。
- 徒步：距离、爬升、返程时间、天气变化、离线能力和风险。

### 3.2 首版能力边界

首版使用真实定位、地图、路线、基础天气和预警数据。摄影机会优先采用可解释的规则算法；AI 负责把已经确认的机会转成自然表达。

以下能力保留接口，但不作为首发阻塞项：

- 全国范围高精度 DEM 通视计算。
- 多数值模型联合精算和集合预报。
- 大规模用户贡献机位社区。
- 实时野生动物追踪。
- 复杂作品发布、社交、比赛和内容信息流。

## 4. 五个主导航

### 4.1 今日

回答“我现在该做什么”。

固定交互语法：

1. 地点与当前情境。
2. 一句话环境结论。
3. 唯一主行动。
4. 最多一个主机会和两个次级机会。
5. 独立安全通道。

按需出现的内容包括拍摄窗口、蓝调、晨雾、倒影、金山候选、星空、人文机会、附近机位、路线变化和野生动物机会。

没有特殊机会时，页面收缩为环境结论、探索入口和轻量灵感瓶入口。

### 4.2 探索

回答“附近有什么值得拍”。

地图是唯一常驻主体，顶部保留搜索，底部使用可收缩抽屉。图层由当前情境和用户意图控制。

可用图层包括：

- 大众机位、小众候选机位和人文点。
- 湖岸、观景点、高点、山口、停车和徒步入口。
- 餐饮、商店、加油站和补给。
- 野生动物模糊分布区、合规观察区域和保护区边界。

纸条可以临时改变地图关注模式。例如“饿了吗”显示餐饮与商店，“去湖边”突出水体与岸线入口。完成操作或意图超时后恢复摄影图层。

### 4.3 路线

回答“接下来会遇到什么”。

无路线时只显示创建路线、导入轨迹和历史路线。有路线后才生成“地图 + 时间轴”。

时间轴串联：

- 出发和预计到达。
- 日出、日落、黄金时刻和蓝调窗口。
- 沿途机位和建议停靠点。
- 加油、餐饮、商店与补给空档。
- 天气、道路、海拔和野生动物风险。
- 徒步阶段的距离、爬升和返程时间。

路线页不承担逐向导航，必要时将确定的目的地或路线交给高德导航。

### 4.4 灵感

回答“我还能拍什么”。

灵感页常驻玻璃瓶、当前环境语境和抽取动作。瓶内纸条由当前情境产生，通常为 2 至 4 个字，可带一个 emoji。

纸条类别：

- 天气创作机会。
- 光线窗口。
- 天象事件。
- 地点探索。
- 人文观察。
- 野生动物拍摄机会。
- 构图建议。
- 生活陪伴。

纸条展开后显示一句解释和确定的动作，例如打开天气、拍摄窗口、地图图层、机位、路线、天象权威页面或 AI 解释。

灵感瓶不是提醒中心。强天气、路线风险和野生动物安全风险永不进入瓶中。

### 4.5 我的

回答“App 应该怎样理解我”。

管理内容包括：

- 个人资料和常驻地区。
- 风光、人文、星空、城市等摄影偏好。
- 自驾、轻徒步、重装徒步和小众探索偏好。
- 相机、镜头、无人机、三脚架和滤镜。
- 收藏机位、路线、纸条和行程。
- AI 语气和推荐强度。
- 离线数据、隐私、定位、通知和缓存。
- 动态背景、减少动态效果、减少闪烁、高对比和省电模式。

## 5. 跨页面核心闭环

```text
今日得到判断
    ↓
灵感产生或强化意图
    ↓
探索选择地点
    ↓
路线安排执行
    ↓
我的沉淀收藏、反馈和偏好
```

所有动态对象都有来源、置信度、有效期和允许动作。事件过期、离开围栏或情境变化后，组件退场且不保留空位。

## 6. 情境主控架构

主控模块命名为 `Context Orchestrator`。它不是单一大模型，而是确定性数据、规则、AI 和 UI 策略的组合。

```text
定位 / 时间 / 天气 / 天象 / 地形 / 路线 / POI / 野生动物 / 用户偏好
                                  ↓
                           统一情境快照
                                  ↓
          场景识别 / 电子围栏 / 机会规则 / 安全规则
                                  ↓
                     候选事件与允许动作集合
                                  ↓
                    AI 表达、解释和辅助排序
                                  ↓
                            UI Manifest
                                  ↓
                      Flutter 动态渲染页面
```

### 6.1 核心模块

- `Context Collector`：采集多源原始数据。
- `Context Builder`：生成具有版本和时间戳的统一快照。
- `Scene Classifier`：识别主场景和辅助场景。
- `Geofence Engine`：计算地理、地形、时间、路线和条件围栏。
- `Opportunity Engine`：产生摄影机会及其置信度和有效期。
- `Wildlife Context Engine`：产生野生动物拍摄机会和安全风险。
- `Safety Engine`：处理天气、路线、徒步和野生动物安全信息。
- `LLM Composer`：生成短词、摘要、解释和个性化语气。
- `UI Policy Engine`：控制组件位置、优先级、数量、动效和退场。
- `Action Router`：执行白名单业务动作。
- `Cache / TTL Manager`：缓存数据并管理事件过期。

### 6.2 状态流约束

- 页面不得自行重复计算天气、场景或机会。
- 所有页面消费同一个有版本的情境快照。
- 安全事件不经过 AI 决定是否展示。
- AI 不得生成候选集合以外的事实或任意页面地址。
- UI Manifest 缺少某一区块时，Flutter 不渲染也不保留高度。
- 快照变化采用情境指纹去重，避免定位微小变化导致频繁模型调用。

情境指纹至少包括地点网格、主场景、时间阶段、天气等级、路线阶段和当前意图。

## 7. AI 边界与降级

### 7.1 AI 可以做

- 把结构化事实压缩为 2 至 4 字纸条。
- 把天气与光线数据解释为摄影语言。
- 在已经成立的多个机会之间辅助排序。
- 根据用户偏好调整语气和解释深度。
- 回答复杂的拍摄、路线和人文探索问题。

### 7.2 AI 不可以做

- 判断天气预警真假或更改预警等级。
- 凭空宣布日食、流星雨、野生动物或日照金山存在。
- 决定电子围栏和事件有效期。
- 编造机位、道路、距离或页面路由。
- 隐藏强制安全事件。

模型输出必须为符合 Schema 的 JSON，并经过来源、有效期、动作白名单、长度、重复和安全冲突校验。

模型不可用时，系统使用事件模板生成基础纸条和摘要。模型增强体验，但不应成为核心功能单点故障。

## 8. 野生动物能力

野生动物能力分为两条互不混淆的通道。

### 8.1 拍摄机会

输入包括物种历史分布、栖息地、海拔范围、季节、迁徙期、昼夜活动规律、近期可信记录和保护区规则。

输出包括：

- 物种或物种类别的可能性，而非确定性结论。
- 推荐观察时段和合规观察区域。
- 建议焦段、安静距离和禁止闪光等规则。
- 数据来源、更新时间和置信度。

机会可以进入今日、探索和灵感瓶，例如“候鸟来了🦅”。

### 8.2 安全风险

大型兽类、野猪、蛇类等风险进入稳定安全通道。输出必须包含风险等级、依据、规避动作、官方来源和有效期。

### 8.3 保护与隐私

- 不公开濒危或敏感物种的精确坐标。
- 敏感记录至少降精度到网格或保护区范围。
- 用户上报经过位置模糊、时间衰减和可信度审核。
- 历史分布只能表达“可能”，不能冒充实时目击或安全保证。
- 官方风险通告优先于社区记录和模型推断。

候选数据源包括 GBIF、IUCN、eBird、国内自然保护区与林草部门公开信息以及合规用户上报。具体商业授权、接口稳定性和国内使用条件必须在接入前逐项核验，不能假定网页数据可直接用于生产。

## 9. 动态环境背景

动态背景命名为 `Ambient Weather Canvas`。它把天气翻译为低干扰的色彩、方向、速度和纹理。

### 9.1 输入与视觉映射

- 天气类型决定基础色与纹理类型。
- 云量决定灰度与对比度。
- 风向决定色场和雨纹方向。
- 风速决定运动速度。
- 阵风决定偶发扰动。
- 降水强度决定雨纹密度、长度和速度。
- 雷暴允许克制的局部亮度脉冲。
- 太阳高度与时间阶段决定亮度和色温。
- 火烧云机会决定暖色渗透程度。

### 9.2 页面强度

- 今日：完整但低饱和的环境色场。
- 灵感：可适当增强，并让玻璃瓶继承环境反射。
- 探索：地图优先，仅保留边缘和抽屉的环境色。
- 路线：只保留轻微色温和状态色带。
- 我的：基本静态。

### 9.3 可读性与性能

- 背景只模糊自身，不模糊文字。
- 正文和安全卡片后方主动压低亮度、饱和度和运动。
- 用户滚动、阅读、打开键盘或弹窗时自动减速。
- 提供完整动态、节能动态和静态环境色三档。
- 跟随系统“减少动态效果”，雷雨闪烁可完全关闭。
- 低性能、发热或低电量设备自动降级。

## 10. 客户端与服务端技术方案

### 10.1 Flutter 客户端

- 状态管理：Riverpod。
- 路由：go_router。
- 本地结构化缓存：Drift。
- 国内地图与定位：高德 Flutter SDK。
- 动态背景：CustomPainter + Fragment Shader 分级实现。
- 灵感瓶：优先验证 Rive 与 Flutter 自绘物理动画，最终选择以真机性能和交互可控性为准。

设备端负责定位、移动状态、基础日月计算、情境缓存、UI Manifest 渲染、动画、离线降级和强制安全信息展示。

### 10.2 服务端

- API 与情境服务：FastAPI。
- 数据库：PostgreSQL + PostGIS。
- 缓存和事件 TTL：Redis。
- AI：通过可替换的模型适配层接入，输出严格结构化 JSON。

服务端负责多源数据聚合、场景识别、摄影机会计算、AI 调用、规则版本、用户偏好、缓存、去重、限流和效果日志。

## 11. 数据源计划

### 11.1 首版核心数据

- 高德：地图、定位、地理编码、POI、自驾和步行路线。
- 和风天气：实况、小时预报、分钟降水、空气质量和官方预警。
- 本地天文算法：日出日落、晨昏、太阳/月亮方位和月相。
- 权威天象目录：日月食、流星雨和彗星事件。
- 自建 PostGIS：机位、山峰、围栏、路线、用户、纸条和场景规则。
- 野生动物：全球分布、鸟类观测、国内官方信息和合规用户上报的组合。

### 11.2 增强数据

- Open-Meteo / ECMWF：高中低云、模型比较和集合预报。
- SRTM / Copernicus DEM：坡度、坡向、遮挡和海拔剖面。
- 地表覆盖：水体、森林、草地、裸地、城市和湿地。
- Wikidata / OpenStreetMap：山峰、山口、水体、小径和偏远设施，需遵守授权与署名要求。

### 11.3 坐标规则

内部保留原始 WGS84；高德展示和高德业务请求使用 GCJ-02。不得使用转换后的坐标覆盖原始坐标，避免地图、DEM、天文计算、路线和电子围栏错位。

## 13. 离线、异常和错误处理

- 定位拒绝：允许手动选择地点，并明确显示非实时状态。
- 网络中断：使用最近的情境快照、缓存路线、本地日月算法和预警缓存。
- 天气过期：显示数据时间，不生成依赖实时天气的高置信机会。
- 模型失败：使用模板摘要与纸条。
- 地图失败：保留已缓存路线、节点列表和必要安全信息。
- 单一数据源冲突：降低置信度并展示来源时间，不伪装成精确结论。
- UI Manifest 解析失败：回退到稳定基础壳，不渲染未知组件或动作。

## 14. 开发阶段

### 阶段 1：产品骨架与视觉基线

完成五个导航、设计令牌、路由、权限流程、空态规则和动态内容容器。用模拟快照验证七类场景下页面会正确收缩。

### 阶段 2：真实环境数据

接入定位、高德地图与路线、和风天气、本地日月算法；建立坐标边界、缓存和错误处理。

### 阶段 3：情境编排系统

实现统一快照、场景识别、电子围栏、摄影机会、安全事件、野生动物机会与风险以及 UI Manifest。

### 阶段 4：五页业务闭环

完成今日判断、探索地图、自驾/徒步路线时间轴、收藏和用户偏好。验证跨页面动作与状态恢复。

### 阶段 5：标志性交互

实现动态天气色场、可读性保护、完整灵感瓶、纸条物理动画、无障碍设置和性能降级。

### 阶段 6：AI 与发布质量

接入结构化模型输出、模板降级、缓存去重、隐私控制、日志和崩溃监控；完成真机、弱网、断网、定位拒绝、数据过期和模型失败测试。

## 15. 验收方法

### 15.1 产品验收

- 打开后 10 秒内给出可以执行的结论。
- 七类场景均能正确改变今日、探索、灵感和动态背景。
- 无效功能不会显示，也不会留下空白位置。
- 纸条动作可以到达确定的目标页面或地图图层。
- 无路线和有路线状态具有明显且合理的界面差异。

### 15.2 安全与野生动物验收

- 强制安全信息不会被隐藏、娱乐化或放入灵感瓶。
- 候鸟迁徙或适宜栖息地能生成有依据的拍摄机会。
- 潜在大型动物活动区能生成独立风险提示。
- 数据陈旧或置信不足时，不输出肯定结论。
- 敏感物种位置只显示模糊区域。

### 15.3 技术验收

- AI、网络或单个数据源失败时核心流程仍可用。
- 所有动态事件均具有来源、时间、有效期和置信度。
- WGS84 与 GCJ-02 数据在真实地点验证无明显错位。
- 动态背景在主流 Android 真机上流畅，并支持关闭或降级。
- 高对比、减少动态和减少闪烁设置有效。

## 16. 主要风险

1. 数据授权风险：野生动物、天象、地图和气象数据的商业授权需逐项确认。
2. 预测可信度风险：摄影机会和动物分布只能表达概率，不能制造确定性。
3. 动态 UI 稳定性：内容可以变化，但页面语法位置必须稳定，避免界面跳动。
4. 性能风险：Shader、毛玻璃和纸条物理动画必须有真机基准与分级降级。
5. 弱网风险：西北和徒步场景网络不稳定，离线缓存不是后续优化，而是首版能力。
6. 坐标风险：国内地图坐标与全球地理数据混用时必须保留明确边界。
7. 安全责任风险：提示必须携带来源、时间和适用范围，不能替代官方指引。

## 17. 首版完成定义

满足以下条件才视为首版完成：

- 五个导航形成完整使用闭环。
- 七类情境有可验证的动态行为。
- 地图、定位、天气和基础路线使用真实数据。
- 灵感瓶与动态环境背景达到可发布质量。
- 摄影机会、安全和野生动物通道边界清晰。
- 离线、无模型、数据过期和权限拒绝均有可用降级。
- 关键逻辑具备自动化测试，核心体验通过 Android 真机验收。
