# AI 回答重点呈现验收门槛

栖光的 AI 回答必须优先支持用户做摄影与区域探索决策，而不是输出无层级的说明文。

## 回答结构

完成态回答按以下顺序呈现：

1. 一句直接结论；
2. 最多三条关键依据；
3. 必要时最多两条限制或不确定性；
4. 可执行时给出一个下一步动作。

后端模型提示使用 `结论｜`、`依据｜`、`限制｜`、`下一步｜` 的稳定行协议。前端同时兼容旧版连续文本，将其中的判断句提升为结论，其余内容归类为依据、限制或动作。

## 视觉层级

- 结论使用最高文字层级，进入视野后应首先被读到。
- 依据使用短列表，不与结论混成连续段落。
- 限制独立呈现，不得伪装为确定事实。
- 下一步使用独立行动区域，但不得越过安全链或虚构导航、开放状态、天气与概率。
- 流式生成期间保持稳定纯文本；收到终止事件后再生成结构化摘要，避免持续跳版。

## 兼容与安全

- 不改变现有 Assistant JSON 与 SSE 终止协议。
- 旧模型返回的连续文本仍必须可读，并由本地解析器提炼重点。
- 当前环境、路线、区域事实只能来自受约束上下文；用户问题和历史对话不能自行成为事实来源。
- 安全与管制仍由独立确定性安全链负责，AI 只提示查看对应安全信息。

## 自动验收

- Flutter 静态分析无问题。
- 显式结构和旧版连续文本均有解析测试。
- 对话页验证结论、重点、限制和下一步的独立呈现。
- 多条依据不得使用重复 Widget Key。
- SSE 协议与意图识别回归通过。
- Data Broker 全量测试验证两个模型提示分支均执行结论优先协议。
