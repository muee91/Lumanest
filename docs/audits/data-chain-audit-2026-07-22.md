# 栖光全项目数据链审计（2026-07-22）

## 审计口径

本报告以当前 `main` 源码、当前 V5 合约和本轮自动化验证为准，不继承旧审计中的结论。每条链按以下边界检查：

```text
可信来源 → Broker/适配器 → 领域归一化 → 新鲜度/缓存
       → 确定性规则 → UI 消费者 → 失败降级 → 回归测试
```

状态定义：

- **闭环**：来源、合约、消费者、降级和测试均存在。
- **条件闭环**：工程链完整，但依赖管理员配置、授权来源、设备权限或区域数据覆盖。
- **受限可用**：只能表达已经成立的一部分事实，不能升级成更强结论。
- **不可用**：关键证据缺失，产品必须隐藏或明确拒绝结论。

## 本轮修复的阻断点

1. **天文数据只到服务端、无法穿过 Broker**：新增 V5 `environment.astronomy` 后同步更新 Context 模型、投影、Broker 严格代理、Flutter 解析和缓存；否则 Broker 会把合法响应判为上游异常。
2. **“精确字段”校验允许缺字段**：Broker Context 代理的 `exactKeys` 现在同时验证字段数量和允许集合，并强制 `sourceRevisions`、`refreshHints`、Astronomy 全部符合当前合约。
3. **月相近似且没有月球/银河轨迹**：用 MIT 许可的 Astronomy Engine 生成精确几何；保留失败降级，不把几何升级成概率或机会。
4. **管理端“清缓存”按钮是假操作**：为内存/Redis 的天气与安全详情、天空机会、城市解析和 7Timer 缓存补齐清除能力，并装配到生产服务。
5. **Context 数据库/Redis 降级与正常空结果不可区分**：关键读链新增枚举化操作名和异常类型日志，禁止记录请求坐标。
6. **Crawler 全局默认开启且来源无法单独授权路径**：默认关闭；只有审核来源显式启用并给出允许路径后才抓取，且当前只允许禁用 JavaScript 的 static 模式。

## 仍然真实存在的边界

### 银河完整推荐

要把 `event.astro.milky_way` 从 unavailable 改为可用，至少还需同时完成：

- 有许可、可更新、可追溯的光污染/夜空亮度数据源及区域分辨率策略。
- 基于 DEM 或审核地平线的目标方向遮挡计算。
- 审核拍摄点、开放时间、合法停车/步行入口和安全冲突。
- 云层、能见度、月球高度与目标方向的同一时段融合，而不是单一评分。
- 端到端校准与真机现场样本。完成前不得显示“银河成功率”或主动通知。

### 其他剩余风险

- 管理端审计日志是进程内最多 200 条，容器重启后丢失；如果作为正式运维审计，需要加密持久化、轮转和保留策略。
- 区域探索的质量取决于实际配置的审核来源覆盖。没有来源时返回 pending/unavailable 是正确行为，不应生成地方软文填充。
- 路线链没有权威全国道路封闭源。Amap 路况、网页候选和天气不能被合并成“道路确定开放”。
- Astronomy Engine 只解决天体几何，不解决光学能见度和现场可达性。
